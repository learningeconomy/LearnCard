# LC-2222 privacy assessment and validation

Reviewed locally on 2026-10-03. This implementation follows [LC-2222](https://welibrary.atlassian.net/browse/LC-2222) and the [LC-2190 research](https://welibrary.atlassian.net/wiki/spaces/LC/pages/1026359297). It is independent of the private verifier-history work in PR #1646.

## Outcome

New Resume Builder publications create one managed Shared entry. Republishing an active associated résumé updates that entry and keeps its address, key and expiry. The generated PDF is encrypted in bounded chunks and retrieved through the same lifecycle policy as the credential. There is no separate public PDF provider URL. Changing title, passcode or expiry in Shared preserves the current attachment; changing résumé content happens in Resume Builder.

The server still learns operational metadata. This implementation does not claim zero additional server knowledge: attachment identifiers, count, ciphertext sizes and request timing are new. It avoids exposing PDF contents, contact fields, selected credentials, digest and decryption key through attachment storage. Existing share titles and lifecycle metadata remain server-visible. No verifier-history records are embedded in the résumé.

## Data inventory

| Data                                                             | Location and reader                                                                                                  | Retention / limitations                                                                                                                                                                                 |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PDF bytes, selected original credentials, visible contact fields | Holder browser; intended recipient after decryption                                                                  | Recipient can retain copies. Selected credentials retain their original signed claims, including claims not shown on the PDF.                                                                           |
| PDF chunks                                                       | Immutable LearnCloud share-content objects; provider sees authenticated owner/tuple and ciphertext size/timing       | Maximum 4 MiB PDF, 256 KiB raw chunks, at most 16. Stop, replacement and safe abandon queue deletion.                                                                                                   |
| PDF key, SHA-256, exact length, attachment descriptor            | Holder-signed LER inside encrypted share manifest; owner private encrypted credential and encrypted retry checkpoint | Key is not a plaintext Brain field or independent provider URL.                                                                                                                                         |
| Owner/profile, share ID, version, attachment UUID/count, policy  | Brain managed share and staging graph                                                                                | Existing managed lifecycle. Expiry denies reads but retains committed ciphertext so the owner can extend expiry.                                                                                        |
| Stage state, completed chunk indices, tombstones, cleanup jobs   | Brain graph / existing immutable storage deletion protocol                                                           | Uncommitted stages expire after 24 hours; bounded maintenance collects them. Cleanup metadata and tombstones are not claimed to be erased immediately. At most eight live uncommitted stages per owner. |
| Passcode verifier and short-lived chunk grant                    | Existing server-side passcode policy; opaque HMAC grant returned to browser                                          | Grant expires after 60 seconds, is bound to current share/version/attachment/passcode/source address, and cannot bypass current lifecycle checks.                                                       |
| Exact pending publication attempt                                | Owner-encrypted IndexedDB checkpoint, maximum 12 MiB                                                                 | Deleted after successful finalization or safe explicit discard. Pending recovery is limited to the same browser; clearing browser storage loses this checkpoint.                                        |
| Resume index / prior private publication URIs                    | Owner personal index and encrypted owner credentials                                                                 | Prior URI history is retained to avoid deleting a credential still referenced by another publication. This is not automatic complete history erasure.                                                   |
| Old résumé URLs                                                  | Existing legacy viewer/provider behavior                                                                             | Republishing does not retract older URLs or already downloaded copies.                                                                                                                                  |

New code uses static diagnostics and does not log filenames, selected URIs, PDF keys, document bodies or exception bodies. The infrastructure continues to observe requests and source addresses under its existing operational policy; this change does not audit or redefine infrastructure log retention.

## Threat assessment

| Threat / failure                                                                          | Control                                                                                                                                                                             | Remaining boundary                                                                                      |
| ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Direct provider URL bypasses stop or expiry                                               | No public provider URL. Gateway derives storage tuple from the committed share and authorizes every chunk, then rechecks state after remote reads.                                  | Ciphertext already obtained cannot be recalled.                                                         |
| Cached credential or attachment descriptor downloads stopped, expired or replaced content | Exact content version and attachment binding on server; download authorization checked before and after retrieval.                                                                  | Previously decrypted or saved bytes remain usable.                                                      |
| Partial upload becomes active, or cleanup races commitment                                | All chunk stats checked before finalization; graph stage pinned under transaction locks. Cleanup withdraws stage authority before remote deletion.                                  | Cleanup requires the configured maintenance worker and retries.                                         |
| Uncertain response creates duplicate Shared entries                                       | Persistent exact attempt and operation key; reconcile create/update before new publication. Index finalization retries stable record identity.                                      | Browser checkpoint loss limits client retry recovery; orphan stages still have server cleanup.          |
| Account switch publishes or hydrates another account                                      | Captured owner and draft identity; account revision checks after asynchronous work, including away/back switches.                                                                   | Tests cover client transitions; deployed session flows still need QA.                                   |
| Swapped chunks, corrupted bytes, descriptor tampering                                     | AES-GCM authenticates share/version/attachment/index/count/length; signed descriptor and digest verified; bounded canonical chunk responses.                                        | An intended recipient holds the decrypted data.                                                         |
| Existing credential proofs invalidated during résumé creation                             | Preserve original credential JSON; LER context treats embedded verification data as JSON. Real DIDKit signing and verification tests cover V1 and V2 sources.                       | Complete signed source claims are included; hiding a PDF field is not source-credential redaction.      |
| Guess budget blocks ordinary multi-chunk downloads                                        | One successful passcode check mints a nonrenewing 60-second grant; all chunks still recheck current policy.                                                                         | Source-address change or expired grant requires another check.                                          |
| Old attachment copied into a different generic share                                      | Protected descriptor must match the target share and content version; use Resume Builder for content publication. Shared metadata editing preserves the existing encrypted content. | Legacy links retain their existing weaker boundary.                                                     |
| Overlarge or malformed PDF                                                                | Reject before public publication; exact-byte integrity checks and 4 MiB limit. Local export remains available with QR disabled.                                                     | Large PDFs require a smaller résumé for managed publication. No silent quality reduction or truncation. |

## Deployment and manual QA

Deploy updated types/SDK and Brain attachment routes before the frontend. Use the existing managed-share storage namespace, authenticated LearnCloud transport, request-hash secret and maintenance configuration; routes fail closed if required configuration is absent. Confirm maintenance actually runs and storage deletion retries succeed. No production deployment was performed for this work.

In a staging environment, publish a new résumé, republish it, edit title/passcode/expiry in Shared, and confirm one entry and a stable URL. Test protected and unprotected downloads in supported desktop/mobile browsers, including a 16-chunk document. Stop or expire during a download and verify no successful export; replace content and confirm old descriptors cannot fetch it. Simulate lost publication and index acknowledgements, then reconcile in the same browser. Confirm a legacy URL still works as documented and that the new UI clearly states copy/legacy limitations. Review retention and original-credential claim disclosure before rollout.

Rollback the frontend publication entry point before rolling back required backend routes. Preserve existing managed data and cleanup processing; removing routes is not a data-erasure procedure.
