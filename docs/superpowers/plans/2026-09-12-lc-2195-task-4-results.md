## Limitations and blockers

1. **Inherited blocker — expired compact VC-JWT renewal.** The pinned
   DIDKit/SSI `jwt_matches` predicate enforces `nbf`/`exp` unconditionally, so a
   signature-valid but expired compact token is indistinguishable from an invalid
   one. `refreshCredential` fails closed with `INVALID_PROOF` and zero network
   requests. Passing an expired held token cannot refresh. Expired JSON-LD held
   credentials do renew after signature/issuer/claim verification. The minimal
   documented fix is an opt-in temporal policy threaded through the pinned fork
   with rebuilt WASM/native artifacts; it was judged out of scope for these
   tasks because the parent gitlinks cannot reference a local-only fork commit.
2. **Unavailable external integration suite.** `tests/e2e/tests/credential-refresh.spec.ts`
   needs live dockerized brain-service/lca-api; the services were down, so it was
   not executed. Unit-level managed/encrypted and signed-JSON regressions passed.
3. **Cross-platform prebuild jobs not run here.** Only the macOS arm64 artifact
   was built and exercised locally. The workflow wiring is added but the matrix
   jobs must run in CI; no unrun job is claimed to have passed.
4. **WASM not rebuilt.** The committed artifact (v0.4.0, pinned `ef269cc`) already
   has the required capability; no fork change was necessary.
5. **VCDM 2.0** is the legacy JOSE `vc`-claim wrapping profile
   (`vc-jwt-2.0-legacy`) only, not general VC-JOSE-COSE conformance. SD-JWT,
   VPR/OID4VCI, managed version-store and notification redesign are out of scope.
