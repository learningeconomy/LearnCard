# LearnCard Network API Client SDKs

## Python regeneration

From the repository root on Linux with Docker available:

```sh
bun install --frozen-lockfile --ignore-scripts
bash packages/open-api-lcn-clients/generate-python.sh
```

The script exports the checked-out brain-service router graph; it does not read a
live deployed OpenAPI URL, start a service, or invoke a route handler. Export and
generation run in network-disabled containers without inherited service
credentials. Bun 1.3.14 and OpenAPI Generator 7.25.0 images are pinned by digest.

Generation writes a sibling staging directory. Security dependency floors and
all their postconditions run against that exact directory before generated
`.github` metadata is removed or the old client is replaced. Output and floor
scripts reject repository ancestors, symlinks, unexpected existing custom
outputs, and unsafe/missing generated metadata. An optional generator output
argument must name a new directory inside this package.
After floor verification and nested metadata cleanup, the same network-disabled
Bun container formats generated Markdown/YAML/JSON with the repository's
`bun.lock`-pinned Prettier and formatting configuration before promotion. This
keeps regenerated bytes reproducible and compatible with the repository CI gate.

The Python templates are vendored from Generator 7.25.0. Stock generated test
scaffolding remains compatible with the generated pytest/tox/CI entrypoints, but
is not behavioral evidence. Maintained contract tests live outside the
replaceable output directory and survive regeneration. Their generation fixes
are in inputs, not hand-edited generated files:

- `from_dict` preserves omitted properties instead of marking them explicitly
  supplied with `None`.
- One-of wrappers accept both wire-shaped `model_validate` input and generated
  `from_dict` construction without losing the actual branch instance.
- Publication schemas own their complete properties, required fields, and
  distinct mode enums. `x-python-forbid-extra` applies only to these two branches
  to preserve `additionalProperties: false`, which the pinned generator loses
  when parsing OpenAPI 3.1. Mixed-mode fields cannot be captured as extra data.
- Date-time query values require a timezone and normalize to the same instant
  in UTC with a `Z` suffix, matching the unchanged server validators. Naive
  datetimes raise a clear `ValueError`; no machine-local timezone is inferred.

The allocation server contract remains optional **but nonnullable**:
`profileId` omission and a string are valid; explicit null is invalid. Python's
optional field annotation still accepts `None`, but an explicitly supplied null
is preserved in prepared JSON rather than silently omitted or made valid. Both
the exported schema and actual source validator reject that prepared payload.

## Offline verification

Use Python 3.14.7 and the complete pinned verification dependency set:

```sh
python -m venv /tmp/learncard-python-verification
/tmp/learncard-python-verification/bin/python -m pip install --no-deps \
  -r packages/open-api-lcn-clients/verification-requirements.txt
(cd services/learn-card-network/brain-service && \
  bun --conditions=development scripts/export-openapi.ts /tmp/openapi.json)
OPENAPI_SCHEMA=/tmp/openapi.json CLIENT_CONTRACT_CAPTURE=/tmp/client-capture.json \
  /tmp/learncard-python-verification/bin/python -m unittest discover \
  -s packages/open-api-lcn-clients/tests -v
(cd services/learn-card-network/brain-service && \
  bun --conditions=development scripts/verify-python-contracts.ts /tmp/client-capture.json)
```

These tests use a synthetic loopback HTTP receiver, not LearnCard or external
services. Public generated APIs exercise real serialization and urllib3
transport. Coverage includes both publication modes and construction paths,
complete nested payloads, optional-field omission, mixed/unknown modes and
missing required fields, allocation omission/string/null, aware and naive date
filters, exact prepared query strings, regex skill-search schemas, and the
unified-send managed receipt schema. Offline document tests preserve distinct
owner/public share routes, authorization requirements, passcode and receipt
boundaries, and bounded owner-list pagination. The capture
is checked against actual Zod validators without calling handlers. PR CI runs
the same checks with network-disabled source-import containers.

Repository shell contracts also run:

```sh
bash .github/tests/test-sdk-security-floors.test.sh
```

Its driver regression records Docker image arguments, rejects non-digest images
and network-enabled runs, and verifies real floor processing and output promotion.
The Docker boundary is synthetic; this test does not pull images or contact services.

For a reproducibility check, generate a new sibling output and compare all
tracked/generated bytes (excluding interpreter caches):

```sh
bash packages/open-api-lcn-clients/generate-python.sh \
  packages/open-api-lcn-clients/.python-client-repeat
diff -qr --exclude=__pycache__ packages/open-api-lcn-clients/python-client \
  packages/open-api-lcn-clients/.python-client-repeat
```
