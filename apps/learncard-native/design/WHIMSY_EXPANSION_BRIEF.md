## Implementation mapping and copy corrections

- **Account:** Keep the existing sheet, profile editor, Families, Data Sharing, language, security, sign-out and forget-device destinations. Notifications/Help and some security/account controls still open on web. Native notification preferences are not implemented. “Forget this device” removes saved access on this device; it does not delete the account. The v2 caption corrects the first draft's ambiguous “Remove your account here”.
- **Data Sharing:** Populate permission labels, scope, recipients, status and expiry from actual agreements. Connection withdrawal and app removal stay separate. “Disconnect app” is a proposed presentation of withdrawal, not an uninstall action. Do not promise that removing access erases copies already shared. The v2 intro uses a neutral description rather than the first draft's “trusted apps” copy. Shared-link Share, Copy and Stop actions already exist; the concept's View link and connection-detail Open app affordances need explicit routing rather than an invented data field.
- **Apps:** Preserve My apps/Discover, category/search, listing details, real catalog artwork/screenshots, access review and in-app browser behavior. Concept app names, preview artwork, counts and selected access are synthetic. Use metadata for the featured card; the generated carousel dots do not establish a multi-feature carousel requirement. Map permission descriptions to actual listing/contract capabilities, not generic promises. Résumé builder stays in the browser.
- **Families:** Preserve existing roster/profile and name/motto/color editing, guardian search against existing accounts, access review, the five-digit secure PIN and confirmed invitation. Splitting recipient selection and review into two screens is a proposed UX refinement over the existing combined sheet, with the same backend flow. Current child setup/switching remains a web fallback. The illustration and additional smiley variants are ideas, not rendered identity or new backend controls.
- **Source assets:** Generated PNG boards are composition references. Recreate approved icons/illustrations as editable SVGs and native layout; do not crop the boards into production assets or replace actual account/app imagery with concept art.

## Approved implementation — 2026-10-15

The user approved these screens for implementation. The native pass applies compact Account groups with editable drawn icon tiles, the illustrated Data Sharing intro and permission rows, artwork-led Apps discovery/details and My apps tools, and a family constellation/roster with separate guardian selection and access/PIN review. Actual names, photos, catalog images, permissions and family appearance remain the data source; the generated example identities and app art are not installed as account data. The consent/link controls retain their existing actual fields and Share/Copy/Stop actions rather than inventing connection dates or unmapped launch destinations.

My apps now has a direct Open action alongside listing details. It uses the same account-owned launch validation, loading feedback and in-app browser as the listing flow; missing/changed access routes to the listing review. Child setup/switching remains on web. Native secure PIN entry uses five masked indicators, clears on submission/background and keeps the existing retry/permission checks. New labels have English, Spanish, French and Arabic translations.

The user also requested tighter header controls and a better scroll transition. Both 44-point controls now share one explicit 96-point pill; the logo and label slot keep their width/position. LearnCard crossfades into the section name on the left, replacing the competing centered UIKit title. Reduce Motion changes the label immediately.

Credential detail motion starts on appearance, with parent scroll geometry controlling offscreen pausing. A nine-second cycle combines 4.5° yaw, 1.8° pitch and a diagonal highlight sweeping across the card. The detail has no stack or drag gesture. Background, Reduce Motion and VoiceOver stay still. Rendered-card regressions verify automatic pixel changes without touch and unchanged pixels with Reduce Motion.

The PNG boards remain visual references; original light/dark SVGs are generated by `scripts/prepare-illustrations.ts`, and native layouts use shared `DrawnUI.swift` components.
